# UI 设计与验收清单 (双语 Tkinter)

> 来源: 2026-07 英文模式按钮截断事故 + 本地化 UI 最佳实践调研。
> 每次改 UI 后跑 `python tools/ui_audit.py`, 全绿 + 抽看截图才算完成。

## 设计规则 (写代码时)

1. **永远不写死字符宽度** —— 中英文宽度差 30~100%。要固定宽度时用
   `i18n.text_units()` 按当前语言的实际文案计算 (拉丁≈1 单位, CJK≈2)。
2. **文案进 i18n.py**, 中文原文当 key; 新增 UI 文案同时补英文翻译。
   英文翻译刻意**短写** (放不下就砍括号里的补充说明, 信息挪到状态栏)。
3. 长文本容器: 固定像素宽 + `pack_propagate(False)` + 像素截断加省略号
   (参考 overlay._fit), 而不是让窗口跟着文本变形。
4. 同一行多段文本: 给每段分配像素预算 (如 状态≤62% 宽), 防互相挤压重叠。
5. Combobox 的下拉条目宽度 = 控件 width, 内容按最长条目算, 设上限防超宽。

## 验收流程 (改完后)

1. `python tools/ui_audit.py` —— zh/en 各构建全部窗口:
   - 截断判据: `winfo_width < winfo_reqwidth` (业界标准做法);
   - Combobox 另按字符单位比内容宽;
   - 隐藏控件 (grid_remove) 跳过;
   - 截图存 `tests/results/ui/*.png`。
2. **人眼看截图** (工具抓不到"内容错但显示正常"类问题, 比如状态文案自相矛盾)。
3. 有截断 → 优先缩短英文文案, 其次放宽容器; 改完回到第 1 步。

## 已知坑

- 审计必须和真实应用同 DPI 模式 (应用是 DPI-unaware); 截图 bbox 用
  `物理屏宽/逻辑屏宽` 换算缩放比, 别开 SetProcessDpiAwareness。
- Tk `width=` 单位是"平均字符宽", 中文按 2 单位估。
- 模型就绪状态判断走 `models.is_ready()` (真实仓库名), 别硬拼 Systran 路径。
