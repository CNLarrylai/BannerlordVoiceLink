# 骑砍语音指挥 · 产品设计简报 (UI Design Brief)

> 给 UI 设计师的交接文档。目的: 为这款软件设计一套**有艺术风格、适合直播**的界面。
> 设计完成后由工程侧 (Claude) 实现。请重点看 §4 界面清单 与 §5 风格方向。

---

## 1. 产品是什么

**一句话**: 用中文语音实时指挥《骑马与砍杀2：霸主》里的军队 —— 你对着麦克风喊"弓箭手散开、全军冲锋"，游戏里的部队立刻执行。

**起源**: 作者是游戏主播，做骑砍直播时用国外软件 VoiceAttack 语音指挥军队，观众觉得很酷。但 VoiceAttack 两个硬伤：① 中文识别很差；② 指令必须精确念、说法不灵活。本产品就是要做一个**中文更准、说法更自由、直播更好看**的替代品。

**长期愿景**: 先做透骑砍，再把这套"语音操作引擎"拓展到其他游戏，形成可变现的产品（多游戏配置切换）。

**它不是什么**: 不是聊天机器人、不是翻译工具。它是一个**实时语音控制器 + 直播视觉道具**。

---

## 2. 目标用户与使用场景

- **主要用户**: 游戏主播（中文），直播骑砍/策略战争类游戏。
- **典型场景**: 一边看着战场、一边跟观众解说、一边用嗓子指挥军队。手要操作角色，所以**语音解放双手**是核心价值。
- **双重受众**: 界面要同时服务两拨人 ——
  1. **主播本人**（配置、调试时看的操作界面）
  2. **直播间观众**（战斗时屏幕上那个"指令浮层"，观众通过它看懂主播在下什么命令）—— 这是"很酷"的来源，**是艺术风格最该发力的地方**。

---

## 3. 差异化 / 核心卖点

| | VoiceAttack | 本产品 |
|---|---|---|
| 中文识别 | 差 | 本地 Whisper，中文准 |
| 说法灵活度 | 精确匹配，死板 | 一句多种说法、口语、儿化音都认 |
| 直播呈现 | 无 | 专门的直播浮层，观众看得懂 |
| 上手 | 复杂 | 双击即用，可视化配置 |

## 4. 需要设计的界面清单 ⭐（本文件重点）

产品目前有 **5 个视觉界面**。下面逐个给出：用途、包含的元素、以及**动态状态**（设计师要为每个状态出稿）。

### 4.1 启动器 Hub（第一眼门面）
双击桌面图标打开的主面板，用户从这里进入各功能。
- **元素**: 产品 Logo/标题、一句 slogan、一个主操作（开始语音指挥）、三个次操作（测试模式 / 音频设置 / 指令词典）、底部提示条。
- **状态**:
  - 待启动（主按钮"开始语音指挥"）
  - 运行中（主按钮变为"运行中"，需要一个"正在工作"的视觉反馈）
- **尺寸**: 桌面窗口，约 460×520，可固定不缩放。

### 4.2 直播指令浮层（★最重要，艺术核心）
战斗时悬浮在游戏画面上、被 OBS 捕获给观众看的小窗。**这是产品的灵魂，观众的"哇"点。**
- **内容**: 当前状态图标/文字 + 识别到的指令（如"✓ 弓箭手 · 散开"）+ 原始识别文字（如"听到: 弓箭手散开"）。
- **状态（每个都要出稿，因为会频繁切换，动效很关键）**:
  1. **待命/监听中** —— 安静待命，可以有轻微"呼吸"动效表示在听
  2. **识别中** —— 短暂的"思考"态
  3. **成功执行** —— 高亮显示"哪个兵种 + 哪条指令"，最出彩的一态，可配合兵种/指令的图标
  4. **未匹配 / 没听清** —— 轻量提示，不打扰
- **强约束（务必满足，否则无法用于直播）**:
  - 背景需**可抠除**：要么纯色便于 OBS 色键（chroma key），要么真透明（PNG alpha）。**不要用会干扰抠图的渐变/杂色背景**，或提供一个"纯色背景版"。
  - 常驻游戏画面之上，**面积要小、不遮挡战场**（建议宽度 ≤ 屏幕 20%）。
  - 文字要**大、高对比、远处能看清**（观众可能在手机小屏看直播）。
  - 中文字体要美观且清晰（书法感可以有，但不能牺牲可读性）。
- **加分项**: 不同兵种（步兵/弓箭手/骑兵/骑射）、不同指令类型（移动/队形/射击）可以有专属图标或配色，让观众一眼分辨。

### 4.3 音频设置
选麦克风的界面。直播设备复杂（作者有 100+ 路音频设备），要能一眼找到在跳的那一路。
- **元素**: 标题说明、一列输入设备（单选）、每路旁边一根**实时音量条**、保存按钮、状态提示。
- **状态**: 音量条随说话实时跳动（有声=绿色条涨落）；已保存提示。
- **尺寸**: 约 860×640。

### 4.4 指令词典（配置中枢）
浏览/添加指令说法、测试一句话会不会被识别、改键位。功能较密，信息层级要清楚。
- **三块区域**:
  1. **词典树**（左）: 兵种 + 指令，每条显示"能说的话（别名）"和"对应按键"
  2. **测试台**（右上）: 输入一句话 → 显示完整判定过程（命中了哪个词、多少分、为什么执行/忽略）
  3. **加说法 / 改键位**（右下）: 表单，选目标 → 填新说法或新键位 → 保存
- **状态**: 测试结果有"会执行"（绿）/"被忽略"（红）两类反馈，需清晰区分。
- **尺寸**: 约 1050×640。

### 4.5 应用图标（桌面 / 任务栏）
- 目前是"令"字（军令）金色圆牌。可重新设计，但要保留**军令/传令**的意象，小尺寸（16–32px）要清晰。

## 5. 风格方向（创作指引，非限制）

- **主题气质**: 中世纪冷兵器战争 + 东方军营点将台。关键词：**军令、传令官、点将、旌旗、羊皮卷、青铜/鎏金、烽火**。
- **不要**: 科技蓝、赛博朋克、卡通萌系 —— 与骑砍的硬派写实战争调性不符。
- **现有视觉基因（可沿用或推翻）**:
  - 深色底 `#101418`、鎏金 `#d4af37`、成功绿 `#7dff9b`、警示红 `#ff8a8a`
  - "令"字作为核心符号
  - 微软雅黑字体（可换更有书法感的中文字体，但需授权且清晰）
- **直播友好**: 深色主调（不刺眼、录播观感好）、高对比、信息一眼可读。
- **一致性**: 5 个界面应共享同一套设计语言（配色、字体、按钮样式、图标风格），像同一个产品。

## 6. 技术约束 & 实现路径（设计师与工程都要看）

**当前技术栈**: Python + Tkinter（桌面 GUI）+ 本地 Whisper 识别。Tkinter 原生控件较朴素，但**可以通过 Canvas 贴位图**实现高度定制的视觉。

因此有两条落地路线，请据此决定交付物形式：

- **路线 A（推荐, 改动小）**: 设计师交付**切好的图片素材**（背景、按钮各状态、图标，PNG @2x 带透明通道）+ 标注稿（间距/字号/坐标）。工程侧用 Tkinter Canvas 把素材拼起来。**几乎能 1:1 还原静态视觉**，适合浮层和 Hub 这类以"美术贴图"为主的界面。动效有限（可做淡入淡出、简单位移）。
- **路线 B（视觉/动效上限更高, 改动大）**: 迁移到 Web 渲染（pywebview + HTML/CSS/JS）。可做复杂动画、粒子、精细排版。代价是重构前端架构、体积变大。**若浮层想要华丽动效（旌旗飘动、鎏金流光），值得走 B。**

> 建议: 浮层（4.2）若追求艺术感和动效 → 倾向路线 B 或至少序列帧动画；其余配置类界面（4.3/4.4）路线 A 足够。请设计师**每个界面标注它期望的动效复杂度**，方便工程选型。

**交付物建议清单**（给设计师）:
1. 每个界面每个状态的**高保真稿**（Figma/PNG 均可）
2. 切图素材（PNG，透明，@2x）
3. 设计规范：色板、字体（含中文字体名与授权）、按钮/图标风格、间距规则
4. 浮层的**纯色背景版**（供 OBS 色键）或透明版
5. 动效说明（哪些元素、怎么动、时长）

## 7. 功能全景（供理解产品，不必逐一设计）

已实现: 持续监听（像 VoiceAttack 常开）/ 中文模糊匹配（口语+儿化音，300+ 说法）/ 聊天误触过滤（区分"下令"和"聊到指令词"）/ 口令前缀（防直播误触）/ 本地 GPU 识别（约 0.4 秒）/ 指令键位可视化编辑 / F10 热重载 / 直播浮层 / 启动器 Hub。

指令覆盖: 选兵种（步兵/弓箭手/骑兵/骑射/全军）+ 动作（前进/后退/冲锋/撤退/跟随/停止 + 队形线阵/盾墙/散阵/圆阵/方阵/楔阵/纵列 + 自由射击/上下马/交AI）。

---

## 8. 命名与语气

- 产品名（暂定）: **骑砍语音指挥** / Bannerlord Voice Commander
- 语气: 硬派、简洁、有军令感。文案用"传令、听令、执行"这类词，而非"点击、确认"。
- 面向观众的浮层文案要口语、有代入感（像真的在指挥打仗）。
